# 0015. The Stop hook's cache key covers what the checks read, as they saw it

- Status: accepted
- Date: 2026-11-08

## Context

Amends [0013](0013-stop-hook-adr-and-check.md). The green-run cache hashed `HEAD`, `git diff HEAD` and the untracked files, and was computed before `check:fast` started (issue #58). Two gaps:

- Gitignored inputs were not in the key. Reproduced: after a green run, moving `node_modules` away left the hash unchanged, so the hook skipped while `check:fast` failed. Deleting `playground/generated` was also skipped; that is harmless today because `typecheck` and `test` delete and regenerate both generated dirs, but it holds only as long as those scripts do.
- A change made while the checks ran (another tool, a second session in the same worktree) was recorded under the state hashed before the run, so the checks never saw that exact state.

## Decision

The hook hashes two parts. The inputs: `HEAD`, the tracked diff (`--binary`, no external diff or textconv), untracked paths and contents, and `node_modules/.pnpm/lock.yaml`, pnpm's record of what it installed (an install that changes `node_modules` changes it, a no-op install does not; `node_modules/.modules.yaml` is left out because it carries a `prunedAt` timestamp). The generated output: the contents of `playground/generated` and `test/fixtures/generated`. The cache key covers both, so a changed or deleted generated dir misses.

After a green run the hook hashes the inputs again and writes the cache only if they equal the inputs before the run, via a temp file and `mv`. The generated dirs are outputs of the run (`typecheck` and `test` regenerate them), so they are not compared; the key is written with the generated output as the checks left it, and the next stop hits without another run. A missing file changes the hash; a file that vanishes while being hashed makes it fail, and a failed hash never hits or writes. The hook works from the top level of the hook input's `cwd`.

The cache stays one file per worktree. Concurrent sessions can overwrite each other's entry, which costs a re-run but never a wrong skip, since every entry's inputs were unchanged by its run.

`.claude/hooks/stop-check.test.sh` covers hit, misses on generated, `node_modules` and untracked changes, changes during the run, output regenerated by the run, a stop from a subdirectory and red runs, with a stub `mise` on `PATH` so the hook itself has no test-only switch.

## Consequences

The checks re-run after an install that changes `node_modules` or after generated output changes outside a run. The before/after comparison cannot see an input that is changed and reverted while the checks run; that state can be cached although the checks read the intermediate one. A generated dir rewritten during the run by something other than the checks is cached as the checks' output. Other gitignored inputs and the environment are not in the key: tool versions, the `oasdiff` binary that `test/codegen.test.ts` skips without, `.env` files, hand edits inside `node_modules`. Add them here if they cause a wrong skip. The hook tests are run by hand (`sh .claude/hooks/stop-check.test.sh`), not in CI.
